# 훅 공식 21개

공식 이름은 Jakeschincariol/youtube-agent-skill(MIT)의 분류를 따랐고, 설명과 예시는 이 프로젝트용으로 새로 썼다. `formula` 필드에는 영문 key를 저장한다.

| key | 이름 | 구조 | 예시 뼈대 |
|---|---|---|---|
| `statistic` | 통계 | 의외의 숫자 하나로 시작 | "직장인 10명 중 7명이 ___ 를 모릅니다." |
| `someone-elses-result` | 남의 결과 | 다른 사람이 얻은 구체적 결과 | "이 사람은 ___ 하나로 3개월 만에 ___ 했습니다." |
| `mistake` | 실수 | 시청자가 하고 있을 실수 지적 | "___ 할 때 대부분 이 순서를 거꾸로 합니다." |
| `contrarian-flip` | 통념 뒤집기 | 다들 믿는 것 → 반대 주장 | "___ 은 사실 시간 낭비입니다. 이유는 ___." |
| `reveal` | 공개 | 숨겨진 것/결과를 보여주겠다 | "6개월 동안 숨겨 온 ___ 를 처음 공개합니다." |
| `superlative` | 최상급 | 가장 ___ 한 것 (근거 필수) | "제가 써 본 것 중 가장 싼데 가장 오래 간 ___." |
| `clock` | 시간 제한 | 짧은 시간 안에 결과 | "10분 안에 ___ 끝내는 방법." |
| `i-tried-it` | 직접 해봤다 | 본인 실험과 기간 | "___ 를 30일 동안 매일 해봤습니다." |
| `question` | 질문 | 시청자가 답을 모르는 질문 | "___ 는 왜 항상 ___ 일까요?" |
| `before-after` | 전후 비교 | 변화 전/후를 바로 보여줌 | "[ON SCREEN: 전/후] 이 차이를 만든 건 단 하나." |
| `teardown` | 해부 | 잘된 것을 뜯어서 분석 | "조회수 100만 나온 ___ 를 한 장면씩 뜯어봅니다." |
| `stack` | 겹쌓기 | 혜택/요소를 연달아 쌓음 | "더 싸고, 더 빠르고, 심지어 ___ 까지." |
| `warning` | 경고 | 하기 전에 꼭 알아야 할 것 | "___ 사기 전에 이것부터 확인하세요." |
| `list` | 리스트 | 개수 약속 | "___ 하는 사람들의 5가지 공통점." |
| `receipt` | 영수증 | 실제 증거(금액·스크린샷) | "[ON SCREEN: 정산 화면] 이번 달 ___ 원, 전부 보여드립니다." |
| `insider` | 내부자 | 업계 안쪽 사람만 아는 것 | "___ 에서 5년 일하면서 알게 된 것." |
| `impossible-claim` | 불가능해 보이는 주장 | 믿기 힘든 주장 + 곧 증명 | "___ 없이 ___ 하는 게 가능합니다. 지금 보여드릴게요." |
| `comparison` | 비교 | A vs B 결론 예고 | "___ 와 ___ , 한 달 써보고 하나만 남겼습니다." |
| `origin` | 기원 | 어떻게 시작됐는지 | "이 모든 건 ___ 한 실수 하나에서 시작됐습니다." |
| `deadline` | 마감 | 곧 바뀌는 것, 지금 알아야 할 이유 | "다음 달부터 ___ 가 바뀝니다. 그 전에 ___." |
| `direct-address` | 직접 호명 | 특정 시청자를 지목 | "___ 하는 분이라면 이 영상은 당신 얘기입니다." |

## 고르는 요령
- 검색 유입형 영상: `question`, `warning`, `mistake`, `list` — 검색어 의도에 바로 답한다.
- 탐색(추천) 유입형: `contrarian-flip`, `i-tried-it`, `reveal`, `impossible-claim` — 호기심과 감정.
- `superlative`, `impossible-claim`, `receipt`는 영상 안에 증거가 있을 때만. 없으면 낚시가 된다.
