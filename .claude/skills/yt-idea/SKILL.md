# 아이디어 → 백로그

입력: $ARGUMENTS (비어 있으면 무엇을 다룰지 묻는다. "소재 추천"이면 `yt-researcher` 서브에이전트로 리서치 후 후보 3~5개를 만든다.)

## 절차

1. `data/channel.json`을 읽어 필러·타깃 시청자·보이스를 파악한다. 없으면 먼저 만들자고 한다.
2. 각 아이디어를 아래 4개 질문으로 거른다. 표로 보여준다.
   - **필러**: 어느 필러 하나에 속하나? 둘 다 걸치면 하나를 고른다. 안 맞으면 "채널 밖"이라고 말한다.
   - **약속**: "이 영상을 보면 시청자는 ___ 를 얻는다" 한 문장. 못 쓰면 아이디어가 아직 흐릿한 것.
   - **패키징 테스트**: 클릭할 이유가 있는 제목 1개 + 썸네일 3어절 이하 문구를 즉석에서 만들어 본다. 안 나오면 보류 권장.
   - **비용**: anchor(공들인) / cheap(기존 자료 재활용) / short 중 무엇인가. 쇼츠면 어느 롱폼에서 파생되나(`parentId`).
3. 사용자가 고른 것만 `data/videos.json`에 추가한다:
   - `id`: 영문 kebab-case slug(짧게), 기존 id와 중복 금지
   - `status: "idea"`, `metrics: []`, `createdAt`/`updatedAt` = 지금 ISO
   - `promise`, `pillarId`, `format`, (있으면) `package.titles`에 테스트 제목
   - 파일이 없으면 `{ "version": 1, "videos": [] }`로 생성
4. 추가한 id 목록을 보여주고 끝낸다. 다음 단계 제안은 한 줄만.

스키마는 `.claude/rules/data-layer.md`를 따른다. 기존 레코드는 건드리지 않는다.
