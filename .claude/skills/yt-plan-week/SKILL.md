# 주간 계획

대상 주: $ARGUMENTS (비어 있으면 Asia/Seoul 기준 이번 주 월요일)

## 1. 지난주 정리 (있으면)
- `data/<채널id>/plans.json`에서 직전 주를 찾아 완료/미완료 슬롯을 보여준다.
- 미완료 슬롯 각각: 이월 / 버림 중 무엇인지 묻는다.
- 한 줄 회고를 받아 그 주 `retro`에 기록한다.

## 2. 이번 주 용량 확인 — 반드시 묻는다
- 이번 주 쓸 수 있는 시간(대략)
- 반쯤 만들어 둔 것이 있는지 (촬영본, 대본 초안 등)
추측해서 채우지 않는다.

## 3. 슬롯 짜기
`data/channels.json`의 해당 채널의 `cadence`와 `stage`를 기본값으로, 용량에 맞춰 줄인다.

| 채널 단계 | 기본 믹스 (경험치) |
|---|---|
| `<1k` | 롱폼 1 + 쇼츠 4~5 |
| `1k-50k` | 롱폼 1 + 쇼츠 3 |
| `50k+` | 롱폼 1~2 + 쇼츠 2~3 |

규칙:
- **anchor** 1개: `data/<채널id>/videos.json`에서 가장 많이 진행된 롱폼 우선. 없으면 백로그에서 패키징이 가장 선명한 것.
- **cheap**: 용량이 남을 때만. 기존 자료 재활용.
- **short**: 가능하면 anchor에서 잘라낸다(`parentId`). 모든 쇼츠는 롱폼과 이어지는 줄기가 있어야 한다.
- 슬롯마다 `due`(요일 날짜)를 단계 역산으로 잡는다: 패키징 → 촬영 → 편집 → 예약.
- 바쁜 주를 기준으로 12주 버틸 수 있는 양인지 마지막에 한 번 묻는다. 과하면 쇼츠부터 뺀다.

## 4. 기록
- 사용자 승인 후 `data/<채널id>/plans.json`의 `weeks`에 추가(같은 `weekOf`가 있으면 교체 여부를 물음). 형식은 `.claude/rules/data-layer.md`.
- 새로 필요한 영상 레코드(예: 파생 쇼츠)는 `status: "idea"`로 `videos.json`에 함께 추가.
- 슬롯에 들어간 영상의 `targetPublishDate`를 갱신.

출력: 요일별 표 1개 + "이 계획으로 갈까요, 바꿀까요?"
