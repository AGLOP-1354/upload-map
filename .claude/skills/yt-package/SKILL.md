# 패키징 (제목 + 썸네일)

대상: `$ARGUMENTS` (video id)

제목과 썸네일은 따로 만들지 않는다. **하나의 약속을 두 채널로** 전달하는 한 단위다.

## 1. 입력 확인
- `data/videos.json`: `promise`, `format`, `hook`(있으면), 기존 `package.titles`
- `data/channel.json`: `voice`, 필러
- 유입 성격을 묻는다(모르면 추정하고 밝힌다): **검색형**(정확한 검색어를 제목에) / **탐색형**(호기심·감정 우선)

## 2. 제목 10개
- 최소 4가지 이상 서로 다른 구조로 (숫자형, 질문형, "제가 해봤다"형, 통념 뒤집기, 경고형, 비교형 …).
- 클릭을 결정하는 단어는 앞쪽 40폭 안에 (모바일 피드 잘림).
- 숫자·이름·날짜 중 하나 이상. 실제 결과가 있으면 "~하는 법"보다 "제가 ~한 방법".
- 대문자 강조 단어 ≤2, 이모지 ≤1, 키워드 나열 금지.
- 영상이 지킬 수 없는 약속 금지.

## 3. 썸네일 문구 후보 3개
- 3어절 이하. 제목의 단어를 반복하지 않는다(다른 단어, 같은 약속).
- 제목이 "무엇"을 말하면 썸네일은 "감정/결과"를 말하는 식으로 역할 분담.

## 4. 린트
```bash
node "${CLAUDE_SKILL_DIR}/scripts/lint-package.mjs" --thumb "썸네일 문구" "제목1" "제목2" ...
```
`issues`가 있는 제목은 고치거나 뺀다. `notes`는 판단 재료로 사용자에게 보여준다.

## 5. 좁히기 + 썸네일 브리프
- 제목 2~3개로 좁힌다(서로 다른 구조여야 A/B 의미가 있음). 하나를 YouTube "Test & Compare" 대표안으로 표시.
- 각 조합(제목 × 썸네일 문구)에 대해 썸네일 브리프:
  - 주인공 1개(얼굴/물건/결과물) — 128×72px 크기에서도 읽히는가
  - 텍스트는 얼굴을 가리지 않음, 배경과 대비 강하게
  - 표정/감정이 있다면 약속과 맞는 감정인가
  - 전·후, 비교, 숫자 등 시각적 대비 요소 하나
- 마지막에 `content-reviewer` 서브에이전트에게 훅·제목·썸네일 약속 일치 검토를 맡긴다. 🔴 항목이 있으면 고쳐서 한 번만 재검토(최대 2라운드).

## 6. 저장 (사용자가 고른 뒤)
- `videos.json` → `package.titles`(최종 후보), `selectedTitle`, `thumbnailText`, `thumbnailConcept`, `updatedAt`
- `content/videos/<id>/package.md` → 10개 전체 후보, 린트 결과 요약, 썸네일 브리프
- `status`가 `idea`/`research`면 다음 단계 이동 여부를 묻는다.

마지막 줄: "이 조합으로 갈까요, 바꿀까요?"
